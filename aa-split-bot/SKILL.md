# aa-split-bot: 朋友聚餐 AA 算账与催款助手

## 概述

朋友聚餐后，算账和催款总是尴尬的。aa-split-bot 可以帮你：

1. **自动触发** — 检测到餐饮场景 + 金额 + 多人，立即启动 AA 流程
2. **解析输入** — 通过 Agent 的 AI 能力解析用户的自然语言描述，提取总金额、参与人列表、付款人
3. **智能计算** — 自动计算每人应付金额（总金额 / 人数）
4. **语气选择** — 根据用户指定或关系亲疏，生成 温和 / 直接 / 幽默 三种风格的催款消息
5. **保存记录** — 将账单以 Markdown 格式追加保存到本地 `records/` 目录

---

## 触发条件（Trigger Conditions）

只要用户的输入 **同时满足以下三个条件**，就应该自动触发 aa-split-bot：

### 条件 A：餐饮场景关键词

用户提到了以下任意一类餐饮/消费场景词（不限于列表，AI 自行判断同类）：

| 类别 | 示例词 |
|------|--------|
| 正餐 | 吃饭、吃饭、晚餐、午餐、早饭、夜宵、食堂 |
| 聚餐 | 聚餐、聚会、团建、请客、拼单、AA |
| 外卖 | 外卖、点餐、叫餐、送餐 |
| 品类 | 烧烤、火锅、黄焖鸡、麻辣烫、奶茶、咖啡、炸鸡、串串、小龙虾 |
| 泛指 | 吃了、吃了点、去吃了、订了 |

### 条件 B：金额描述

用户明确提到了一个具体数字金额，或包含以下表达：

- 花了 / 用了 / 付了 / 出了 + 数字
- 总共 / 一共 / 合计 + 数字
- 数字 + 块 / 元 / 钱
- "AA" + 数字

### 条件 C：多人场景

用户提到了 **至少 2 个参与人**，表现形式包括：

- 显式列表："我、张三、李四" / "我和小明王强"
- 隐含复数："我们仨" / "三个人" / "宿舍四个人"
- 代词 + 人名："我和小王" / "小明和小红跟我"

### 触发判定逻辑

```
IF (条件A 成立)
   AND (条件B 成立 — 可解析出具体金额)
   AND (条件C 成立 — 可识别出 >= 2 人)
THEN → 自动触发 aa-split-bot AA 算账流程
```

**即使没有明确的"帮我算一下"或"AA"字样，也触发。**

### 反例（不触发）

- "今天花了 50 块吃早餐"（只提到一个人，非聚餐场景）
- "食堂涨价了"（无金额、无多人）
- "帮我算一下 3 个人 200 块怎么分"（缺少餐饮场景词 → 仍建议触发，因为"分"暗示费用分摊）
- 注：当金额 + 多人同时出现，即使缺餐饮词也应**模糊匹配触发**，漏触发比误触发更影响体验

## 何时使用

- 用户描述了一段餐饮消费，附带金额和多人信息（无论是否明确请求 AA）
- 用户说"今天吃了 X 花了 Y 我和 A B"
- 用户要求生成催款消息并发给朋友，或指定了语气（温和/直接/幽默）
- 用户要求汇总月度账单（"这个月花了多少钱"、"汇总一下上个月"、"谁欠我最多"）
- 用户反馈某人已付款（"小明转了"、"小红付了"）
- 用户要求用飞书催款（"在群里催一下"、"用飞书发催款"）
- 用户查询未付状态（"谁还没付"、"还有谁没给钱"）
- 用户需要查看或管理历史 AA 账单记录

**不要用于：**
- 非餐饮场景的多人财务计算（用计算器即可）
- 涉及折扣、税费、小费、按比例分摊的复杂场景（此版本为 MVP，仅支持等额 AA）
- 纯单人消费场景
- 跨年或跨多个月的账单汇总（设计为月度粒度，如需跨月可多次调用后手动合并）

## 催款消息语气选择

### 三种语气

Agent 根据用户输入判断语气，规则如下：

| 语气 | 用户关键词（常见） | 适用关系 | 风格描述 |
|------|-------------------|----------|----------|
| 温和 | 没特别说、客气点、礼貌些、请帮我 | 默认、普通同学、同事、不太熟 | 礼貌客气，给足面子 |
| 直接 | 直接说、干脆点、好兄弟、哥们、室友 | 好朋友、室友、熟人间 | 简单明了，不绕弯子 |
| 幽默 | 搞笑点、皮一下、整活、幽默些、调侃 | 铁哥们、死党、群聊活跃气氛 | 轻松玩笑，缓和催款尴尬 |

### 用户指定语气的方式

用户在输入时可以通过以下方式指定语气（不限于这些表达，AI 自行理解意图）：

- 温和："帮我算一下，语气客气点" / "温和地说"
- 直接："直接跟他们说" / "帮我算算，直接点" / "他们都是兄弟，直接要就行"
- 幽默："帮我搞个搞笑的催款" / "幽默点" / "皮一下"

### 默认规则

```
IF 用户明确指定了语气 → 使用指定语气
ELSE IF 用户描述了关系（"好兄弟/室友/铁哥们"） → 根据关系推断：亲近→直接，很铁→幽默，一般→温和
ELSE → 默认使用 温和
```

## 工作流

### Step 1：检测触发条件 → 解析用户输入 & 语气

用户输入可能是隐式的，例如：

> "今天吃饭花了96，我和小明王强"

**自动检测到：** 餐饮场景("吃饭") + 金额(96) + 多人(我、小明、王强) → 启动 AA 流程。

**同时检测语气：** 用户没指定语气，默认 → 温和。

另一个例子：

> "昨天和宿舍哥们吃烧烤花了280，直接跟他们说"

**解析：** total=280, participants=["我","宿舍哥们"或具体人名], payer="我", **语气=直接**。

**作为 Agent，你需要用 AI 能力解析出：**

| 字段 | 说明 | 示例值 |
|------|------|--------|
| total | 总金额（浮点数） | 96.0 |
| participants | 参与人列表（列表） | ["我", "小明", "王强"] |
| payer | 付款人（字符串） | "我" |
| tone | 语气（字符串） | "温和" / "直接" / "幽默" |

解析注意事项：
- "我"保留为参与人，说"你"时转换为用户的名字（如有记忆）或保留"你"
- 付款人默认为"我"（用户自己），除非明确提到别人付钱（"他付的"、"张三请客"等）
- 日期信息：如果用户说"昨天/前天/上周"，尝试推算具体日期，填充到催款消息中
- **语气检测**：从用户输入中提取语气关键词，未指定则归入默认规则

### Step 2：调用脚本计算与保存

使用结构化参数调用 `scripts/aa-split.py`：

```bash
python scripts/aa-split.py --total <总金额> --participants <参与人列表> --payer <付款人>
```

示例：

```bash
python scripts/aa-split.py --total 96 --participants 我 小明 王强 --payer 我
```

> **注意：** 脚本输出的催款消息是默认版本（温和风）。**不要直接展示脚本的默认消息**，继续 Step 3 进行语气重写。

### Step 3：根据语气重写催款消息

脚本返回后，提取其中的金额、参与人等信息，然后 **用 Agent 的 AI 能力重新生成** 符合所选语气的催款消息。

三种语气的核心风格对照（保持信息完整，只改措辞和语气）：

#### 温和风（默认）

**风格：** 礼貌、客气、给面子。适合普通同学、同事、不太熟的人。

**示例模板：**
```
--- 聚餐账单 | 7月11日 ---

各位好，昨天的 XX 账单出来了，麻烦大家看一下~

总金额：XXX 元
参与人：XXX（共 X 人）
每人应付：XX 元
付款人：XXX（已垫付）

方便的话请尽快转给 XXX 哦，谢谢大家！
```

**关键措辞：** "麻烦"、"请"、"谢谢"、"方便的话"、"~"结尾

#### 直接风

**风格：** 干脆利落，不绕弯子。适合好兄弟、室友、熟人。

**示例模板：**
```
--- 聚餐账单 | 7月11日 ---

兄弟们，昨天的 XX 账算好了。

总金额：XXX 元 | 共 X 人
每人：XX 元
付款人：XXX（已垫付）

记得转我哈，谢啦！
```

**关键措辞：** "兄弟们"、"直接说"、"记得转我哈"、"谢啦"、无多余客套

#### 幽默风

**风格：** 轻松、调侃、缓和催款尴尬。适合铁哥们、死党、群聊活跃气氛。

**示例模板：**
```
--- 催债通知书 | 7月11日 ---

尊敬的顾客您好，您的 XX 账单已生成~

总金额：XXX 元
您的份额：XX 元
付款人：XXX（已含泪垫付）

老板催债了！速速转账保平安！
```

**关键措辞：** "催债通知书"、"尊敬的顾客"、"含泪垫付"、"速速转账保平安"、"不然拉去烧烤摊抵债"等调侃用语

#### 语气重写规则

1. **保持信息完整：** 日期、总金额、每人金额、付款人，四大要素一条不能少
2. **只改措辞和语气：** 不要修改金额数字
3. **付款人信息保留：** 始终说明谁是垫付人、转给谁
4. **群聊风格适配：** 如果是发到微信群，开头可以加 @所有人 或群昵称呼
5. **不要过度玩笑：** 幽默风以轻松为主，不要冒犯或让真的欠钱的人不舒服

### Step 4：将结果呈现给用户

向用户展示：
- 简明的计算结果（总金额、参与人、每人应付）
- **语气重写过**的催款消息（可直接复制发群）
- 已保存的文件路径

同时标注当前使用的语气（方便用户确认或要求切换）。

### Step 5：保存催款消息到文件

脚本自动将账单以 Markdown 格式保存到 `records/` 目录，文件名格式：`YYYY-MM-DD_HHMMSS.md`

**注意：** 文件中保存的是脚本输出的默认催款消息（温和风），而不是语气重写后的版本。如需保存语气版本到文件，Agent 可以在展示给用户后，询问用户是否需要将语气版本也追加到记录文件中。

## 可选模式

### 自然语言模式（脚本自带简易解析）

如果无法使用 AI 解析（或想快速测试），可以直接将自然语言文本传给脚本：

```bash
python scripts/aa-split.py "今天聚餐花了200块，我、张三、李四一起吃的，我付的钱"
```

脚本内置正则解析器会尽力提取信息。但对于复杂表述，AI 解析更可靠。

### JSON 模式（供程序化调用）

```bash
python scripts/aa-split.py --total 200 --participants 我 张三 李四 --payer 我 --json
```

输出 JSON 格式的结果，适合被其他工具链消费。

### Dry Run 模式

```bash
python scripts/aa-split.py --total 200 --participants 我 张三 李四 --payer 我 --dry-run
```

仅打印结果，不保存文件。

## 月度账单汇总

### 何时触发

当用户说以下任意一句话（或含义类似）时，自动触发月度账单汇总功能：

- "帮我汇总一下这个月的账单"
- "我这个月吃饭花了多少钱"
- "汇总一下上个月的"
- "谁欠我最多"
- "这个月的聚餐统计"
- "看看我这个月的AA记录"
- "六月账单汇总一下"

检测逻辑：

```
IF 用户提到 汇总/总结/统计/查看 + 账单/花销/记录/欠款/AA
   OR 用户提到 时间范围（这个月/上个月/几月）+ 花了/账单/汇总
THEN → 触发月度汇总流程
```

### 工作流

#### Step 1：确定目标月份

从用户输入中提取时间范围：

| 用户说 | 目标月份 |
|--------|----------|
| "这个月" | 当前月份（根据系统日期） |
| "上个月" | 当前月份 - 1 |
| "六月" | 当年 6 月 |
| "去年十二月" | 去年 12 月 |
| 什么都没说 | 默认当前月份 |

**当前日期基准：** 以系统当前日期为准。如果今天是 2026-07-11，则"这个月" = 2026-07，"上个月" = 2026-06。

#### Step 2：读取 records/ 目录下的所有 .md 文件

使用工具列出 records/ 目录内容：

```python
# Agent 执行步骤示意（用 search_files 或终端 ls）
from hermes_tools import terminal
result = terminal("ls records/*.md 2>/dev/null || dir /b records\*.md 2>nul")
```

或直接在终端/代码中列出目录下的 Markdown 文件。

#### Step 3：按文件名日期过滤目标月份

文件名格式为 `YYYY-MM-DD_HHMMSS.md`，提取前 7 个字符 `YYYY-MM` 与目标月份匹配。

示例：`2026-07-11_210123.md` → 月份 `2026-07`

只保留文件名前缀月份与目标月份一致的记录。

#### Step 4：解析每份账单记录

对每份匹配的 .md 文件，用 `read_file` 读取内容，然后通过正则提取关键字段：

```python
import re

text = "读取的文件内容..."

# 提取总金额
total_match = re.search(r"总金额\s*\|\s*([\d.]+)\s*元", text)
total = float(total_match.group(1)) if total_match else 0

# 提取参与人列表和人数
people_match = re.search(r"参与人\s*\|\s*(.*?)（共\s*(\d+)\s*人", text)
participants_str = people_match.group(1) if people_match else ""
people_count = int(people_match.group(2)) if people_match else 0

# 提取付款人
payer_match = re.search(r"付款人\s*\|\s*(.*?)$", text, re.MULTILINE)
payer = payer_match.group(1).strip() if payer_match else ""

# 提取每人应付金额
per_person_match = re.search(r"每人应付\s*\|\s*([\d.]+)\s*元", text)
per_person = float(per_person_match.group(1)) if per_person_match else 0

# 提取文件名中的日期
import pathlib
fname = pathlib.Path(file_path).stem  # "2026-07-11_210123"
date_part = fname[:10]  # "2026-07-11"
```

提取的字段说明：

| 字段 | 来源 | 用途 |
|------|------|------|
| date | 文件名前 10 字符 | 展示账单日期 |
| total | 表格中的"总金额"行 | 计算月度总支出 |
| participants_str | 表格中的"参与人"行 | 统计各人参与次数和欠款 |
| people_count | 表格中的"共 N 人" | 验证 |
| per_person | 表格中的"每人应付"行 | 验证 |
| payer | 表格中的"付款人"行 | 判断垫付人 |

#### Step 5：计算统计指标

将所有账单数据汇总后，计算以下指标：

**A. 本月聚餐总次数**

```
总次数 = len(匹配的账单文件)
```

**B. 本月聚餐总支出**

```
总支出 = SUM(每笔账单的总金额  where 付款人 == "我")
```

注意：只统计"我"作为付款人的账单（即用户垫付的部分）。如果用户问的是"这个月总共花了多少钱"，则统计所有账单的总金额。

**C. 人均单次消费**

```
人均单次 = 总支出 / 总次数  （保留两位小数）
```

**D. 欠款排行榜**

遍历每一笔账单，对于 participants_str 中解析出的每个参与人（排除"我"自己），累加他们每笔应付的金额：

```
欠款[人名] += 该笔账单的每人应付金额
```

最后按欠款金额从高到低排序。如果有 N 笔"我"付款的账单，某人在其中出现了 M 次，则欠款 = M * 该笔每人应付金额。

**注意：** 同一人可能在不同账单中使用不同称呼（如"小明"和"小明同学"）。Agent 在解析时应用 AI 能力进行合理的人名去重合并，但在无法确定时，优先保持原始名称并标注"可能存在重复统计"。

**E. 本月账单明细列表**

按日期排序，列出每笔账单的日期、金额、参与人。

#### Step 6：生成汇总报告

以 Markdown 格式输出报告，结构如下：

```markdown
# 月度聚餐账单汇总

### 概览（汇总报告模板示例）

| 指标 | 数值 |
|------|------|
| 统计月份 | 2026 年 7 月 |
| 聚餐总次数 | X 次 |
| 本月总支出 | XXX 元 |
| 人均单次消费 | XX 元/次 |

### 欠款排行榜（汇总报告模板示例）

| 排名 | 欠款人 | 累计欠款（元） | 参与次数 |
|------|--------|---------------|----------|
| 1 | 小明 | 160.00 | 2 |
| 2 | 王强 | 80.00 | 1 |

### 本月账单明细（汇总报告模板示例）

| 日期 | 金额（元） | 参与人 | 付款人 |
|------|-----------|--------|--------|
| 07-10 | 240.00 | 我、小明、王强 | 我 |
| 07-11 | 96.00 | 我、小明、王强 | 我 |
```

#### 汇总触发检测清单

- [ ] "帮我汇总一下这个月的账单" → 触发
- [ ] "我这个月吃饭花了多少钱" → 触发
- [ ] "看看上个月的AA记录" → 触发，月份为上个月
- [ ] "汇总一下六月的" → 触发，月份为当年6月
- [ ] "今天吃什么" → 不触发（无汇总意图）
- [ ] 汇总报告包含：总次数、总支出、人均消费、欠款排行、明细列表
- [ ] 欠款排行榜从高到低排序
- [ ] 日期从文件名正确提取

## 支付状态追踪与飞书催款

### 概述

记录每笔账单的支付状态，支持标记已收/未收、在飞书群发起催款 @ 对应欠款人，以及查询未付状态。

### 数据文件

所有支付状态存储在 `records/payment_status.json`。如果文件不存在，Agent 首次使用时自动创建。

#### 数据结构

```json
{
  "bills": [
    {
      "bill_id": "2026-07-11_204933",
      "total": 96.00,
      "participants": ["我", "小明", "王强"],
      "payer": "我",
      "status": {
        "小明": "unpaid",
        "王强": "unpaid"
      }
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
|------|------|
| bill_id | 对应 records/ 下的文件名（不含扩展名） |
| total | 该笔账单总金额 |
| participants | 参与人列表 |
| payer | 垫付人 |
| status | 字典：key=参与人姓名，value="paid" 或 "unpaid" |

### 工作流

#### 流程 A：新增账单时自动创建或追加状态记录

**触发条件：** Agent 每次成功调用 `aa-split.py` 生成新账单记录后。

**执行步骤：**

1. 检查 `records/payment_status.json` 是否存在，不存在则创建 `{"bills": []}`
2. 读取当前文件内容
3. 构造新账单的状态条目：

   ```python
   import json
   bill_entry = {
       "bill_id": "YYYY-MM-DD_HHMMSS",    # 从刚刚保存的 .md 文件名提取
       "total": 总金额,
       "participants": ["我", "小明", "王强"],
       "payer": "我",
       "status": {}
   }
   # 对所有非"我"的参与人，初始化为 "unpaid"
   for p in 参与人列表:
       if p != "我" and p != 付款人:
           bill_entry["status"][p] = "unpaid"
   ```
4. 将新条目 append 到 `bills` 数组
5. 写回 `payment_status.json`

**注意：** 如果付款人不是"我"（比如张三请客），则不需要为任何人创建 status 条目（不用催别人还张三的钱）。

#### 流程 B：标记某人为已付款

**触发条件：** 用户说以下任意一句（或含义类似）：

- "小明已经转了"
- "小红付了"
- "王强给钱了"
- "小明已支付"
- "收到小明的钱了"

**执行步骤：**

1. 从用户输入中提取人名（如"小明"）
2. 读取 `records/payment_status.json`
3. 遍历 `bills` 数组，找出所有 `status` 中该人状态为 `"unpaid"` 的条目
4. 将这些条目的 `status[人名]` 更新为 `"paid"`
5. 写回文件
6. 向用户汇报更新结果：

   > "已将小明标记为已付款，共更新 4 笔账单，累计 272 元。"

**边界情况：**
- 如果该人已经全部 paid，提示"小明已经全部付清了，不需要重复标记"
- 如果找不到该人，提示"未找到 {人名} 的未付款记录"
- 如果用户说"他们都转了"或"全部付清了"，则将所有 `unpaid` 标记为 `paid`

#### 流程 C：查询未付状态

**触发条件：** 用户说以下任意一句（或含义类似）：

- "谁还没付"
- "还有谁没给钱"
- "查看未付账单"
- "欠款状态"
- "催款进度"

**执行步骤：**

1. 读取 `records/payment_status.json`
2. 遍历 `bills`，聚合所有 `status` 中值为 `"unpaid"` 的条目，按人汇总：

   ```python
   debt = {}  # {人名: {"total": 金额, "count": 笔数, "bills": [bill_id列表]}}
   for bill in data["bills"]:
       for name, status in bill["status"].items():
           if status == "unpaid":
               if name not in debt:
                   debt[name] = {"total": 0, "count": 0, "bills": []}
               debt[name]["total"] += bill["total"] / len(bill["participants"])
               debt[name]["count"] += 1
               debt[name]["bills"].append(bill["bill_id"])
   ```
3. 按欠款总额降序排列，生成报告：

   ```
   ## 未付款状态

   总未付金额：XX 元 | 未付人数：X 人

   | 欠款人 | 未付金额（元） | 未付笔数 | 账单日期 |
   |--------|---------------|----------|----------|
   | 小明 | 272.00 | 4 | 07-11, 07-11... |
   | 王强 | 272.00 | 4 | 同上 |
   ```
4. 如果全部已付清，提示"所有人都已经付清了，干得漂亮！"

#### 流程 D：飞书群催款

**触发条件：** 用户说以下任意一句（或含义类似）：

- "在飞书群里催一下"
- "用飞书催款"
- "飞书发催款消息"
- "帮我催一下"
- "发飞书"

**前置要求：**
- Hermes 已配置飞书网关（用户提供 app_id 和 app_secret）
- 用户已在当前对话或记忆中指定了飞书群聊的 chat_id

**执行步骤：**

##### Step D1：聚合未付数据

读取 `payment_status.json`，按人聚合所有 unpaid 条目（同流程 C）。

##### Step D2：构造催款消息

根据用户之前指定的语气（温和/直接/幽默，默认温和）构造消息。

飞书消息支持 Markdown 格式，示例：

```text
@小明 @王强
各位老板，7月的聚餐账单该清一下啦！

小明欠 272 元（4 笔），王强欠 272 元（4 笔）

方便的话请尽快转给我哦，谢谢大家！
```

##### Step D3：通过飞书网关发送

使用 execute_code 调用飞书网关 API：

```python
from hermes_tools import web_search  # 或其他 HTTP 能力

# 调用飞书网关发送群消息
# Hermes 的飞书网关配置在 config.yaml 中
# 发送 POST 到飞书 API 发送群消息
```

**实际执行方式：** Hermes 通过已配置的飞书网关发送消息。Agent 在终端或 execute_code 中调用飞书消息发送接口。

Agent 需要从用户记忆或对话中获取飞书群 `chat_id`。如果用户尚未提供，主动询问："请告诉我飞书群聊的 chat_id。"

##### Step D4：确认发送结果

- 发送成功后，向用户汇报："已通过飞书向 X 人发送催款消息"
- 发送失败时，提供催款文本让用户手动复制发送作为兜底

## 常见陷阱

1. **漏触发** — 用户说"三个人吃了串串 180"没有"AA"或"算账"字样，但仍应触发。三条件检测可以避免漏触发。
2. **单人误触发** — "今天吃麻辣烫花了25"只一个人，不触发。
3. **参与人不够 2 人** — 脚本会报错退出。如果用户只提"我和张三"，记得 count=2 即可。
4. **金额解析失败** — 如果金额格式不标准（如"八十块"），AI 解析后再用结构化模式调用脚本。
5. **records/ 目录权限** — 脚本会自动创建 `records/` 目录，但如果上级目录没有写入权限会失败。可以通过 `--records-dir` 参数指定其他目录。
6. **Python 路径** — 确保在正确的 Python 虚拟环境中运行脚本，依赖均为 Python 标准库。
7. **付款人不在参与人中** — 脚本会自动处理，催款消息会提示"转给付款人"。
8. **错过模糊匹配** — 当金额 + 多人同时出现但缺少餐饮场景词时，仍应主动询问"你们是聚餐吗？需要帮忙 AA 算账吗？"而不是沉默。
9. **直接展示脚本默认消息** — 脚本默认输出温和风消息。**如果用户指定了直接或幽默语气，必须用 AI 重写**，不要偷懒直接展示脚本输出。
10. **语气推断错误** — 用户说"和兄弟吃了500"，暗示关系亲近，应推断为**直接风**而非温和。不要机械匹配关键词，要理解关系语义。
11. **幽默风过头** — 幽默催款要让人会心一笑，不要真的冒犯到欠款人。"不转钱就拉黑"这种话不适合。保持"催款但不伤和气"的底线。
12. **切换语气时丢失信息** — 重写催款消息时，确保日期、总金额、每人金额、付款人这四大要素完整保留。
13. **records 目录为空** — 用户要求汇总但 records/ 目录不存在或为空时，友好提示"还没有就餐记录，先去吃一顿吧！"而不是报错。
14. **文件名日期解析失败** — 如果 records/ 目录中有不符合 `YYYY-MM-DD_*.md` 格式的文件，应跳过并提示用户该文件无法解析。
15. **付款人不是"我"的情况** — 汇总"总支出"时区分"我垫付"和"别人垫付"。欠款排行榜只统计欠"我"的金额，别人垫付的账单不计入。
16. **人名去重不一致** — 同一人可能在不同记录中写法不同（"小王" vs "王强"）。在汇总欠款时用 AI 判断是否同一个人，无法确定时保留原始名称并加脚注。
17. **跨月请求** — 只支持单月汇总。如果用户说"汇总一下上半年的"，提示"目前只支持按月汇总，请指定具体月份"。
18. **payment_status.json 尚未初始化** — 如果用户说"谁还没付"但 `payment_status.json` 不存在，提示"还没有支付追踪记录，请先生成一笔账单"而不是报错。
19. **飞书 chat_id 未配置** — 如果用户说"用飞书催款"但没有提供 chat_id，主动询问群聊 ID，而不是直接失败。
20. **重复标记已付款** — 用户可能多次说"小明付了"，应检查状态已经是 paid 的跳过，并提示"小明已标记过了"。
21. **同一人不同称呼** — 记录中写"小明"但用户说"小明同学付了"。用 AI 判断是否为同一人，无法确定时确认后再更新。
22. **飞书消息格式** — 飞书 Markdown 中 @ 用户需要使用 `@user_id` 或 `open_id`，不能只写 `@小明`。如果只有名字没有 ID，使用文本格式的 @名字（飞书文本消息支持 @人名 但不触发通知）。Agent 需根据可用的飞书 API 能力决定实现方式。
