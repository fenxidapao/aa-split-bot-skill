# aa-split-bot: 朋友聚餐 AA 算账与催款助手

> 一个基于 Hermes Agent 的智能 Skill，解决朋友聚餐后 AA 算账和催款的尴尬问题。从自然语言输入到飞书群催款，覆盖"算账 → 催款 → 追踪 → 汇总"全链路。

---

## 项目简介

aa-split-bot 是一个运行在 Hermes Agent 上的智能 Skill，用户只需用自然语言描述聚餐场景（"今天和小明王强吃了黄焖鸡花了96"），它能自动：

1. **解析** 出总金额、参与人、付款人
2. **计算** 每人应付金额
3. **生成** 不同语气的催款消息
4. **保存** 账单记录到本地
5. **通过飞书** 直接在群里催款
6. **追踪** 谁的款已付、谁还在欠

---

## 核心功能

| 功能 | 说明 | 版本引入 |
|------|------|---------|
| **自然语言解析** | AI 解析用户的自然语言输入，提取 total / participants / payer | v1.0 |
| **自动触发** | 检测"餐饮+金额+多人"三条件，即使没有"AA/帮我算"字样也自动触发 | v2.0 |
| **催款语气选择** | 温和 / 直接 / 幽默 三种语气，根据用户指定或关系亲疏自动匹配 | v3.0 |
| **月度账单汇总** | 自动扫描 records/ 目录，生成包含总次数、总支出、欠款排行榜的月度报告 | v4.0 |
| **飞书群催款** | 通过飞书开放 API 在群聊中发送 @ 催款消息 | v5.0 |
| **支付状态追踪** | 持久化记录每人每笔的 paid/unpaid 状态，支持"XXX已经转了"一键更新 | v5.0 |

## 使用方式

### 安装

1. 确保已安装 Hermes Agent
2. 将 aa-split-bot Skill 目录放入 `~/.hermes/skills/` 或通过 `skill_manage` 注册
3. 配置飞书网关（可选，用于飞书催款）：
   - app_id 和 app_secret 在 Hermes 配置文件中设置

### 触发示例

| 你说 | 发生什么 |
|------|---------|
| "今天和小明吃饭花了88" | 自动算账，每人 44 元，温和催款 |
| "昨天和兄弟吃烧烤240，直接跟他们说" | 直接风催款消息 |
| "三个人吃火锅200，帮我搞个搞笑的催款" | 幽默风催款消息 |
| "帮我汇总一下这个月的账单" | 月度统计报告 + 欠款排行 |
| "在飞书群里催一下" | 飞书群发催款消息 |
| "小明已经转了" | 更新支付状态 |
| "谁还没付" | 查看未付列表 |

## AI 核心价值说明

aa-split-bot 的核心竞争力在于大模型的以下能力，这是纯规则代码无法替代的：

### 1. 自然语言理解（NLU）

```
用户输入："昨天中午和宿舍的小明、王强一起吃了黄焖鸡，总共花了 96 块"
                     ↓
AI 解析：total=96, participants=["我","小明","王强"], payer="我", date="昨天"
```

传统正则表达式无法处理"宿舍的小明"、"黄焖鸡花了96"等灵活表述，AI 可以从语义层面理解。

### 2. 语气风格迁移

同样的数据（总金额 240，小明/王强各 80），AI 能生成三种完全不同风格的文本：

- 温和："方便的话请尽快转给我哦，谢谢大家~"
- 直接："记得转我哈，谢啦！"
- 幽默："老板催债了！速速转账保平安！"

传统模板引擎需要预先编写所有变体，而 AI 可以无限微调。

### 3. 模糊匹配与意图识别

```
"今天和小明王强吃了烧烤花了240" → 没有"AA/帮我算"但 AI 判断需要触发算账
"食堂涨价了"                             → 虽然提到吃，但 AI 判断不需要触发
```

这种基于上下文和语义的意图识别，规则系统难以覆盖所有边界情况。

### 4. 上下文感知与关系推断

- "和兄弟吃了500" → 推断关系亲近 → 自动选择直接风
- "和老板吃了800" → 推断需要礼貌 → 选择温和风

AI 能理解"兄弟"和"老板"在人际关系语义上的差异，并据此调整行为。

### 5. 同名去重与人名消歧

- records 中写"小明"，用户说"小明同学付了" → AI 判断是同一人
- "老板小明"和"小明" → AI 判断是否为同一人

这种基于语义的判断能力远超简单的字符串匹配。
